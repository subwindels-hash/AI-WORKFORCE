## Summary

Fixes the reported `Sync pulled nothing. First error: api-football: provider
error: The Page field do not exist.` on the Sports Intelligence console — the
reason **Today's intelligence** showed 0 scheduled / 0 live / 0 qualified
predictions and the 30-day performance panel stayed empty.

`ApiFootballProvider::fetchAllPages()` prepended `page=1` to **every** request:

```php
$resp = $this->doRequest($path . '?' . http_build_query($params + ['page' => $page]));
```

api-football v3 answers an unaccepted query parameter with HTTP 200 and
`errors: {"page": "The Page field do not exist."}`. `/fixtures` (a whole day or
a whole season in one response) and `/leagues` (everything) do not paginate, so
that one optional parameter failed the entire call. `decodeJson()` correctly
refused to read the empty `response` as "no data" — so the sync stored nothing
and `Sports::sync()` surfaced the provider message verbatim.

Reproduced against the real provider class before any change:

```
/fixtures?date=2026-09-05&page=1  → ProviderException (DATA_ERROR): provider error: The Page field do not exist.
/leagues?page=1                   → provider error: The Page field do not exist.
```

### Changes

- **`fetchAllPages()`** — `page` is no longer sent on the first request (page 1
  is the provider default). Follow-ups send `page=N` from 2 upwards while
  `paging.current < paging.total`, hard cap 40 pages, so the genuinely
  paginated endpoints (`/odds` at 10/page, `/players` at 20/page) still come
  back complete. Also drops the stray trailing `?` when no filter is set
  (`/leagues` instead of `/leagues?`).
- **Graceful degradation** — a follow-up page refused *because the endpoint
  does not accept `page`* keeps the rows already fetched and records the
  truncation instead of throwing the whole pull away. Every other provider
  error still propagates, so a mid-pull auth or quota failure is never
  swallowed into a silently short result set.
- **`ProviderException`** — new `details` array (4th optional ctor argument,
  backwards compatible). `decodeJson()` now populates `details.errorField`
  from the API's own error key, so the rejected parameter is detected from a
  fact rather than by pattern-matching the message.
- **Truncation is visible, not hidden** — `paginationNotes()` /
  `resetPaginationNotes()` on the transport trait, reported through
  `health()['paginationNotes']` and the live-smoke fixtures step. A short pull
  still passes as ONLINE but names what could not be read.
- **`docs/SPORTS_PROVIDERS.md`** — the API-Football pagination section is
  rewritten. It previously claimed the v3 list endpoints all paginate with
  `page` (fixtures at 50/page), which is what the buggy call was built on.

### Tests

- `tests/cases/88-sports-native-providers.php` — +6 tests: no `page` on the
  first request against a page-rejecting API, `/leagues` fetched without a
  page parameter, page-1 rows kept when `page=2` is refused (with the note
  asserting the provider message and row count), truncation surfaced through
  `health()`, unrelated errors from a follow-up page still thrown, and an
  **end-to-end `syncFixtures()` run** through the real `SportsSyncService` +
  `SportsRepositoryStub` proving today+tomorrow lands 4 stored matches and
  audits `SPORTS_FIXTURE_SYNC_COMPLETED`.
- `tests/cases/96-sports-live-smoke.php` — +1 test: a truncated pull still
  passes the smoke test and the report names `page 2 refused`.
- The pre-existing pagination assertions that pinned the old behaviour
  (`assert_true(str_contains($urls[0], 'page=1'))`) are updated to assert the
  corrected contract.
- Suite: **182 tests across 19 sports suites, 0 failures** (88: 61 → 67 passed,
  96: 7 → 8 passed). Reverting only the source and keeping the new tests
  reproduces **7 failures in 88 and 1 in 96**, so the coverage is a real
  regression guard.
- The DB-backed suites (50, 51, 70, 93, 100) fail identically before and after
  this change with `Call to undefined function get_instance()` — they need a
  live CodeIgniter + MySQL. Same failure counts on the pristine base commit,
  so no regression, but they are unexercised here.

### Note for operators

This unblocks fixture and odds ingestion. Ticket-grade decisions still report
`MODEL_NOT_CALIBRATED` until an administrator approves a calibration
(`PredictionEngine.php:12`, `PredictionPipeline.php:114`) — that gate is
intentional and untouched by this change.
