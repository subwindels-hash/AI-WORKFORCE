## Summary

Fixes the reported `Refused: signed-in identity lacks 'sports.manage' — the sync
action was not performed.` on the Sports Intelligence console. Two defects
combined: the console handed every signed-in identity a working-looking
**Sync now** button (and approve/reject/settle forms), and the permission check
was taken against the session identity snapshot captured at sign-in — so a role
granted afterwards stayed invisible until the next sign-in, while a revoked
permission kept working until logout.

### Changes

- **`MY_Controller::refreshIdentityPermissions()`** (new) — re-reads the signed-in
  identity's permissions from the database before *every* permission decision
  (sports console guard, JSON API `requirePermission()`, admin page gate), at
  most once per request, and rewrites the session snapshot when it changed. A
  grant applies on the very next action; a revocation stops working
  immediately. A database error keeps the snapshot the session was issued with,
  so an outage never silently grants or revokes access.
- **`Sports::sportsCaps()`** — resolves `sync` / `approve` / `settle` for the
  signed-in identity; `base()` passes `caps` into both console views. Controls
  render only when the identity holds the permission; otherwise a disabled
  control names the missing permission and how to obtain it — no dead-end POST
  targets.
- The refusal message now names the role to ask for and states that no sign-out
  is needed.
- **`tests/framework.php`** — added `assert_not_contains()`.

### Tests

- New `tests/cases/100-sports-permission-freshness.php` — behavioural coverage
  of the refresh helper against a stub session + identity repository: role
  granted after sign-in applies immediately, a revoked permission stops working
  at once, exactly one database read per request, anonymous requests read
  nothing, and a database failure preserves the signed-in snapshot (plus source
  assertions pinning the console gating).
- `tests/cases/50-sports-dashboard-ui.php` — a read-only identity now renders no
  mutation POST targets at all, and the missing permission is named.
- Suite: **680 passed, 3 failed**. The same 3 failures exist on the base commit
  (`4fec730`) — two lottery CSRF source assertions and one chat-assistant
  mapping test — so this change introduces no regressions (674 → 680 passing,
  +6 new tests).

### Docs

`docs/SPORTS_PRODUCTION_REVIEW.md` records the finding, the remediation and the
cases that pin it (production-review finding #3), and the go/no-go checklist now
notes that role grants apply on the next action.

### Verified in the live preview

Signed in as a read-only member (`platform_member`, `sports.view` only) the
Sports page shows **Sync now (needs sports.manage)** disabled with the reason;
signed in as a super administrator the real `POST /sports/sync` form is
rendered.
